# Сервис «Очередь обращений»

Fullstack-приложение: пользователь создает обращение через веб-интерфейс, сервис асинхронно обрабатывает его в фоне и обновляет статус.

## Быстрый запуск

Убедитесь, что у вас запущен **Docker Desktop**. 

В корне проекта (там, где лежит `docker-compose.yml`) выполните:
```bash
docker compose up --build -d
```

После запуска всё готово к работе:

| Сервис | Внутренний порт | Внешний порт | Адрес / Доступ | Описание |
|---|---|---|---|---|
| **Frontend (UI)** | `80` | `3000` | `http://localhost:3000` | Интерфейс для работы с обращениями |
| **Backend (API)** | `8000` | `8000` | `http://localhost:8000` | REST API |
| **Swagger UI** | `8000` | `8000` | `http://localhost:8000/docs` | Документация API и тестирование эндпоинтов |
| **Health-check** | `8000` | `8000` | `http://localhost:8000/health` | Проверка статуса бэкенда |
| **Метрики** | `8000` | `8000` | `http://localhost:8000/metrics` | Проверка метрик |
| **PostgreSQL** | `5432` | `5432` | `localhost:5432` | База данных (user: `app`, pass: `app`, db: `tickets`) |
| **Redis** | `6379` | `6379` | `localhost:6379` | Брокер очередей |


## ✅ Чек-лист выполнения ТЗ

### Обязательная часть (90 баллов)
- [x] **API (REST, OpenAPI):** создание, список с фильтром по статусу и пагинацией, карточка обращения.
- [x] **Статусы:** `queued → processing → done | failed`. Недопустимые переходы возвращают `409`, ошибки валидации `422`.
- [x] **База данных:** одна миграция (Alembic), составной индекс `(status, created_at DESC)` под фильтр и сортировку, поля `created_at` и `updated_at`.
- [x] **Очередь:** ARQ + Redis. Настроены ретраи, реализована идемпотентность (повторная обработка не создает дубль).
- [x] **Воркер:** имитация обработки 2–5 секунд, при ошибке статус меняется на `failed` с записью причины в БД и лог.
- [x] **Frontend:** список, форма создания, автообновление статусов (polling каждые 2 сек), состояния загрузки, пустого списка и ошибки (React + TS + TanStack Query).
- [x] **Запуск:** `docker compose up --build` поднимает приложение, БД, Redis, воркер и фронтенд без ручных шагов.
- [x] **Тесты:** 3 обязательных сценария (переходы статусов, ошибка воркера, интеграционный тест API) запускаются одной командой `pytest -q`.
- [x] **README:** описание запуска, архитектуры, решений, компромиссов и использования ИИ.
- [x] **Инфраструктура:** `.env.example` без секретов, seed-записи (3 тестовых обращения), `.gitignore`.
